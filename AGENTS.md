# Расширение «Счета магазина»

Репозиторий — проект 1C:EDT с расширением `СчетаМагазина`. Основную конфигурацию он не содержит и не должен менять.

База в том же рабочем пространстве EDT: `../AI_IS_03`, имя проекта `AI_IS_03` (`DT-INF/PROJECT.PMF`). Это демонстрационная «Библиотека стандартных подсистем» 3.2.1.569, `БиблиотекаСтандартныхПодсистемДемо`, режим совместимости 8.5.1, язык скрипта русский. Метаданные читать оттуда: `../AI_IS_03/src/<Вид>/<Имя>/<Имя>.mdo`.

## Формат исходников

Это EDT, не выгрузка конфигурации в файлы.

- Объект: `src/<Вид>/<Имя>/<Имя>.mdo`, модуль рядом — `Module.bsl`.
- Состав расширения: `src/Configuration/Configuration.mdo`.
- Кодировка UTF-8. Язык модулей — русский (`Процедура`, не `Procedure`).
- Не создавать `Configuration.xml`, `ConfigDumpInfo.xml`, `Ext/Module.bsl`.
- Существующие UUID не переназначать. Новому объекту метаданных — новый UUID.
- Новые объекты расширения называть с префиксом `СчетаМагазина`.
- Общие модули оставлять серверными. Клиент, внешнее соединение, вызов сервера и привилегированный режим не включать.
- Расширение — дополнение (`AddOn`), назначение и режим — безопасные (`Checked`), совместимость 8.5.1. На небезопасный режим не переключать.

## Два слоя, которые нельзя смешивать

Публичный HTTP-контракт и предметная логика счетов сейчас расходятся. Источник маршрутов — `src/HTTPServices/СчетаМагазина/СчетаМагазина.mdo`, не спецификация.

Сервис `СчетаМагазина`, RootURL `objects`, повторное использование сеансов `AutoUse`, `sessionMaxAge` 20. Шаблоны:

| Метод | Шаблон | Обработчик |
| --- | --- | --- |
| GET | `/types` | `НайтиТипы` |
| GET | `/type` | `ОписатьТип` |
| GET | `/search` | `НайтиОбъекты` |
| GET | `/object` | `ПрочитатьОбъект` |
| POST | `/object` | `СоздатьОбъект` |

Обработчики возвращают `501` / `not_implemented`. Проверка этих путей — `tests/objects.http`.

Общие модули реализуют другой, уже написанный контракт счетов из `docs/superpowers/specs/2026-10-25-shop-invoices-design.md`:

- `СчетаМагазинаМетаданные` — документ `_ДемоСчетНаОплатуПокупателю`, схема по живым метаданным, разрешённые справочники.
- `СчетаМагазинаДанные` — разбор JSON, поиск, заполнение и чтение счёта.
- В модуле HTTP-сервиса уже есть транспорт для этого контракта: JSON-ответы, путь поля штатного сообщения, журнал, `403`/`500`. К текущим заглушкам он не подключён.

Спецификация описывает RootURL `shop-invoices` и пути `/schema`, `/catalogs/{name}`, `/invoices`, `/invoices/{id}`, а также каталог `src/extensions/`. Этого в репозитории нет. План в `docs/superpowers/plans/` считает ту реализацию принятой в другом дереве исходников.

Пока задача явно не выбирает один из слоёв:

- не переписывать шаблоны HTTP под спецификацию и не удалять общие модули как мёртвый код;
- не реализовывать `/types` и `/object` вызовами логики счетов и не выдавать это за выполнение спецификации;
- не переносить в код ручной список реквизитов счёта.

## Инварианты логики счетов

Их соблюдать при любой правке `СчетаМагазинаДанные` и `СчетаМагазинаМетаданные`.

- Схема строится из метаданных базы с расширениями. Новое поле появляется само. Составные и неподдерживаемые типы остаются в описании; неподдерживаемый тип делает поле недоступным для записи.
- Для записи доступна только `Дата` среди стандартных реквизитов; она обязательна. Ссылка, номер, пометка удаления и проведение назначает платформа.
- Табличная часть `ДополнительныеРеквизиты` описывается и не записывается. Проверку свойств БСП не отключать и не подменять значениями.
- Магазин передаёт суммы. Цены, скидки, НДС и автозаполнение документа сервис не считает и не вызывает.
- Неизвестные ключи и поля с `writable=false` отклоняются. `null` — пустое значение типа 1С.
- Строку не обрезать, число не округлять, строку не превращать в число или булево. Дата — ISO 8601 без `Z` и без смещения; часть «Дата» — `YYYY-MM-DD`.
- Ссылка — UUID существующего доступного элемента разрешённого справочника, не группа и не помеченный на удаление. Нет объекта и нет прав — один и тот же отказ, без сообщения, существует ли элемент.
- Имя справочника в запросе берётся из метаданных allowlist, не из строки пользователя. Значения — только параметрами. Поиск: `ПОДОБНО` и `ОбщегоНазначения.СформироватьСтрокуДляПоискаВЗапросе`, `ВЫБРАТЬ РАЗРЕШЕННЫЕ`.
- Запись счёта — без проведения, без `ОбменДанными.Загрузка`. `ПроверитьЗаполнение()` в транзакции; отказ или исключение откатывает транзакцию, документ не остаётся.
- Повтор заказа не идемпотентен. Защиту от дублей не добавлять втихую.
- Тело запроса и данные авторизации в журнал не писать. Событие журнала — `СчетаМагазина`. Клиенту при сбое — краткий текст, подробности — в журнал.
- Ошибка: `{"error":{"code","message","details":[{"path","message"}]}}`. `path` только из точного поля сообщения платформы, иначе `null`.
- Ответ: `Content-Type: application/json; charset=utf-8`, UTF-8 без BOM.
- Привилегированный режим не включать. Чтение и запись идут с правами пользователя HTTP-сервиса.

Внешние ключи JSON (`header`, `tables`, `id`, `error`) английские. Имена процедур и реквизитов 1С — русские.

## Запросы

Текст запроса собирать так, чтобы имя таблицы уже прошло сверку с метаданными. Пользовательский фрагмент в текст запроса не подставлять.

Для условий сверяться с индексами объекта в `.mdo` базы. У ссылочных объектов есть индекс по ссылке; у справочника с наименованием — по наименованию. `ПОДОБНО` по наименованию допустим как условие по этому индексу. Новый индекс в расширении не заводить без отдельной задачи.

## Проверка

- `tests/objects.http` — REST Client. Адрес, авторизация и UUID читаются из `tests/.env` (`OBJECTS_URL`, `OBJECTS_AUTH`, `PARTNER_ID` и соседние идентификаторы). Значения `.env` не печатать и не коммитить.
- Открытие счёта в 1С:Предприятии и сравнение списка документов выполняет пользователь. Vanessa не использовать. Успешный HTTP-ответ не называть проверкой формы.
- Контрольные данные брать существующие. Партнёров, номенклатуру и настройки базы не создавать.
- Загрузку расширения в информационную базу выполнять только по явной просьбе. В этом репозитории нет скриптов стенда; команды загрузки не выдумывать.

## Что не менять попутно

- `../AI_IS_03` и любые объекты основной конфигурации.
- Спецификацию и план, пока пользователь не просит привести их к коду или наоборот.
- Уже принятые UUID, префикс, RootURL и имена обработчиков.
- `tests/.env`.
