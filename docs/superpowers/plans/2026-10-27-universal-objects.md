# Универсальный HTTP-сервис объектов — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Один сервис описывает, ищет, читает и создаёт справочники и документы; счёт на оплату создаётся тем же `POST /object`.

**Architecture:** Общий модуль `СчетаМагазинаМетаданные` строит схему любого справочника или документа. `СчетаМагазинаДанные` преобразует JSON, ищет и читает объекты. Модуль HTTP-сервиса остаётся транспортом: параметры, статусы, транзакция записи, журнал. Старые функции одного документа удаляются в той задаче, где у них не остаётся вызывающего.

**Tech Stack:** EDT-расширение, BSL, HTTP-сервис платформы 8.5.1, REST Client (`tests/objects.http`), файл `tests/.env`.

**Spec:** [docs/superpowers/specs/2026-10-27-universal-objects-design.md](../specs/2026-10-27-universal-objects-design.md)

## Global Constraints

- Расширение `СчетаМагазина`, каталог исходников `src/`. Основную конфигурацию не менять.
- UUID сервиса и модулей, RootURL `objects`, `AutoUse`, `sessionMaxAge` 20, имена обработчиков `НайтиТипы`, `ОписатьТип`, `НайтиОбъекты`, `ПрочитатьОбъект`, `СоздатьОбъект` не менять.
- Общие модули серверные. Клиент, внешнее соединение, вызов сервера и привилегированный режим не включать.
- Имя типа в маршруте: `Справочник.<Имя>` или `Документ.<Имя>`. Имя типа значения в схеме: `CatalogRef.<Имя>`, `DocumentRef.<Имя>`, `EnumRef.<Имя>`, `string`, `number`, `boolean`, `date`, `ValueStorage`, `UUID`.
- Внешние ключи JSON английские. Имена реквизитов 1С русские.
- Ответ: `Content-Type: application/json; charset=utf-8`, UTF-8 без BOM.
- `null` — пустое значение типа. Строку не обрезать, число не округлять, строку не превращать в число или булево. Дата — ISO 8601 без `Z` и без смещения; часть «Дата» — `YYYY-MM-DD`.
- Нет объекта и нет прав на ссылку — один отказ, без сообщения, существует ли объект.
- Имя таблицы запроса берётся из уже сверенных метаданных. Пользовательский фрагмент в текст запроса не подставлять. `ВЫБРАТЬ РАЗРЕШЕННЫЕ`. Новый индекс не заводить.
- Запись без `ОбменДанными.Загрузка` и без `Заполнить` / обработки заполнения. Документ — `РежимЗаписиДокумента.Запись`, после записи он не проведён. `ПроверитьЗаполнение()` в транзакции; отказ или исключение откатывает транзакцию.
- Повтор POST не идемпотентен. Защиту от дублей не добавлять.
- Журнал: событие `СчетаМагазина`. Тело запроса, авторизацию и содержимое хранилища не писать.
- Проверку дополнительных свойств БСП не отключать и не подменять значениями. Если она блокирует контрольное создание — остановиться и согласовать границу.
- `tests/.env` не печатать и не коммитить. Vanessa не использовать. Успешный HTTP не называть проверкой формы.
- Загрузку расширения выполняет пользователь по своей просьбе. Команду загрузки не выдумывать: в репозитории нет скриптов стенда. До загрузки живой маршрут отвечает `501` / `not_implemented`. GREEN по HTTP заявлять только после этой загрузки.

## Review Focus

Эти случаи нельзя закрыть запросом из `tests/objects.http` на текущей базе. Реализация всё равно следует спецификации; проверяющий читает код названной функции.

1. Помеченный на удаление объект по `GET /object` возвращается с `header.ПометкаУдаления=true`, а `GET /search` его не возвращает. Пометку в базе не ставить. Код: `ПрочитатьОбъект` не фильтрует пометку, `НайтиОбъекты` фильтрует.
2. Справочник с длиной наименования 0: поиск отвечает `400`, запрос не строится. В этой конфигурации такого справочника нет. Код: проверка `ДлинаНаименования` до `Новый Запрос`.
3. Чтение без прав и чтение отсутствующего объекта дают один `404` и текст «Объект не найден». Второй учётной записи в `.env` нет. Код: нет права чтения — `Неопределено` без отдельного текста.
4. Проведённый документ допустим как значение ссылки. Отдельного уже проведённого документа проверка не требует. Код: запрос ссылки на документ не содержит `Проведен`.
5. Общий реквизит поддерживаемого типа при чтении попадает в `header`, запись ключа отклоняется. Набор общих реквизитов сверяет проверяющий по ответу `GET /type`, не по списку в этом плане. Код: `writable=false` и причина «Общие реквизиты этой версией не записываются».

- [ ] **Step 3: Реализовать разбор имени, список типов и схему**

`РазобратьИмяТипа`: одна точка, непустые вид и имя. Вид только `Справочник` или `Документ`. Объект ищется `Метаданные.Справочники.Найти` / `Метаданные.Документы.Найти`. Чужой вид — `unsupported`, даже если имя существует. Пустое или без точки — `malformed`.

`НайтиТипы`: `СокрЛП`, сравнение через `НРег` по `Имя` и `Представление()`. Сортировка по `name`. В выборку попадает `Лимит + 1` имя, наружу — не больше `Лимит`, `hasMore` по лишнему элементу. Шаблоны не интерпретировать.

`СхемаОбъекта`: в поля входят реквизиты, которые есть у объекта, а не весь список EDT.

- Наименование — при `ДлинаНаименования > 0`, запись разрешена, `required` из проверки заполнения.
- Код — при `ДлинаКода > 0`. Автонумерация: `writable=false`, reason `Код назначает 1С`. Иначе запись разрешена.
- `ЭтоГруппа` — только иерархия групп и элементов, запись разрешена, `required=false`.
- `Родитель` — при любой иерархии, запись разрешена.
- `Владелец` — при непустых `Владельцы`, запись разрешена, `required` из проверки заполнения.
- `Ссылка`, `ПометкаУдаления`, `Предопределенный`, `ИмяПредопределенныхДанных`, у документа `Номер` и `Проведен` — в схеме, `writable=false`, reason `Стандартное техническое поле назначает 1С`.
- `Дата` документа — `writable=true`, `required=true`.
- Стандартные реквизиты строки, включая `НомерСтроки`, — `writable=false`.
- Таблица `ДополнительныеРеквизиты` — `writable=false` и reason про БСП. Её реквизиты описываются.
- Общий реквизит включать, если в составе этого объекта использование `Использовать`, либо `Авто` при автоиспользовании `Использовать`. `writable=false`, reason `Общие реквизиты этой версией не записываются`.
- Любой `unsupported` среди типов поля делает всё поле недоступным для записи. Описание типа в `types` остаётся.

`rules`:

- `validation` = `Окончательное решение принимает штатная проверка заполнения 1С; условные правила зависят от данных и настроек базы`
- `dates` = `ISO 8601 без Z и без смещения; часть Дата — YYYY-MM-DD; дата-время — местное время базы`
- `null` = `null — штатное пустое значение типа`
- `amounts` = `Суммы передаёт клиент; сервис их не рассчитывает и не вызывает заполнение`
- `valueStorage` = `Хранилище значения — base64 текста элемента ValueStorage штатной XML-сериализации, без тегов`

`ОписаниеТипа`: ссылка на документ — `kind=document`, `name=DocumentRef.<Имя>`, `document`, `searchUrl`. Хранилище — `ValueStorage` / `valueStorage`. Уникальный идентификатор — `UUID` / `uuid`. Часть даты «Время» по-прежнему `unsupported`.

Обработчики HTTP берут `q`, `name`, `limit` из параметров запроса. Пустой после `СокрЛП` `q` и `limit` вне 1…100 — `400`. Отсутствующий `limit` равен 20. `unsupported` → `400` и текст `Вид метаданных не поддерживается`. `not_found` → `404` и текст `Тип не найден`. `malformed` → `400`, path `name`. Успех — `200` и JSON схемы или списка.

- [ ] **Step 3: Реализовать подготовку значений и транзакцию**

`Подготовить` отклоняет неизвестные ключи верхнего уровня кроме `type`, `header`, `tables`. Для документа отсутствующая или пустая `Дата` — ошибка path `header.Дата`, текст `Дата обязательна`, ещё до транзакции.

Ссылка на справочник в обычном поле — `СсылкаДоступна(..., "element")`: существует, не помечена, и при иерархии групп `НЕ ЭтоГруппа`. Ссылка на документ — `"document"`: существует и не помечена, без условия `Проведен`. `Родитель` при `folders` — `"group"` (`ЭтоГруппа`). `Родитель` при `items` — `"element"`. `Владелец` — ровно одна доступная элементарная ссылка среди `Мета.Владельцы`; ноль или больше одной — та же ошибка недопустимой ссылки.

Запрос ссылки: `ВЫБРАТЬ РАЗРЕШЕННЫЕ Ссылка ИЗ Справочник.<ИмяИзМетаданных> ГДЕ Ссылка = &Ссылка И НЕ ПометкаУдаления` и при необходимости `И ЭтоГруппа` или `И НЕ ЭтоГруппа`. Имя из метаданных владельца или поля, не из JSON.

`Base64ВХранилище`: обернуть текст в элемент `ValueStorage` пространства `http://v8.1c.ru/8.1/data/core` и прочитать `ПрочитатьXML`. Неудача — ошибка поля, объект не создаётся. `null` — пустое хранилище через `ОписаниеТипов.ПривестиЗначение`.

UUID: принять строку только если она равна `XMLСтрока` результата. `null` — пустой идентификатор.

Обработчик создания:

1. Тип тела начинается с `application/json`, иначе `415`.
2. Разобрать JSON до конца потока. Хвост — `400`.
3. `РазобратьИмяТипа`. Нет права `Добавление` — `403`, `forbidden`, текст `Недостаточно прав на операцию`.
4. `Подготовить`. Ошибки — `400`, `invalid_request`, без записи.
5. Транзакция. Очистить сообщения `ПолучитьСообщенияПользователю(Истина)`. Создать объект менеджером метаданных, `Заполнить(Объект, Данные)`. Не вызывать `Объект.Заполнить()`. Не устанавливать `ОбменДанными.Загрузка`.
6. `ПроверитьЗаполнение()` ложно — откат, `422`, все сообщения, path только из точного поля.
7. Документ записать `РежимЗаписиДокумента.Запись`. Если `Проведен` — откат и `500`. Справочник — `Записать()`.
8. Ответ — `ПрочитатьОбъект` внутри транзакции, затем фиксация. Исключение — откат и `НепредвиденнаяОшибка`. Успех — `201`.
